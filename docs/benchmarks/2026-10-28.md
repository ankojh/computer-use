# Synthetic Codex planning latency — 2026-10-28

Operator requested a benchmark before any active model-setting change. Both model
settings and the currently installed app were left unchanged by this benchmark.

## Method

- OpenAI Codex app-server with existing ChatGPT subscription authentication.
- Three fixed configurations, **no classifier call**: Luna-low, Luna-medium, Astra-medium.
- Two rounds, rotating configuration order; three cases each, **18 total planner calls**.
- Generated 1152×720 PNGs; no real screenshots, user data, network browser, or physical input.
- Cases: locate Compose; recover from a simulated failed click after Compose moves;
  stop when a requested CMU profile/sender conflicts with visible Personal profile/account.
- Each recovery reuses its configuration's planner thread. Other cases start fresh
  providers. Reported total time therefore includes cold setup for two of the three cases.
- Plans are returned as data only: this example does not instantiate a Mac platform or
  agent/executor. The only platform implementation used is in-memory `FakePlatform`.

## Results

| Fixed configuration | Samples | Planner median | Planner range | Total-call median | Narrow checks |
|---|---:|---:|---:|---:|---:|
| Luna / low | 6 | 2.350 s | 1.393–3.281 s | 2.897 s | 6/6 |
| Luna / medium | 6 | 2.631 s | 1.353–2.741 s | 2.851 s | 6/6 |
| Astra / medium | 6 | 4.135 s | 2.554–4.427 s | 4.541 s | 6/6 |

All click coordinates landed within the fixture's expected button rectangles; all
six mismatch responses returned no actions and explicitly identified Personal versus
CMU and the wrong sender. These are intentionally easy/narrow checks, **not general
planning, identity-verification, or safety guarantees**.

Luna had lower planner latency in this small sample. Low versus medium differs by
only 281 ms in median planner time, and the total-call medians are effectively tied;
these data do not establish that low is always faster. Removing the separate router
call is the more obvious latency saving. Subscription load, longer conversations,
real screenshots, and consequential/ambiguous tasks can behave differently.

For context only (not a controlled comparison): the earlier real desktop run
`20261028-222237-272b59c0` selected Astra on all 14 planning turns. Median classifier
latency was 2.898 s and median planner latency 4.336 s; median complete model-response
latency was 7.240 s. Routing itself was a substantial part of the wait.

## Reproduce (opt-in subscription usage)

```sh
swift tools/render-benchmark.swift target/benchmark-fixtures
cargo run -p cu-providers --example latency_bench -- \
  target/benchmark-fixtures target/benchmarks/latency.json
```

The example makes exactly 18 planner calls on success, saves after each reply, and
fails rather than silently substituting an unavailable explicit model. No live
configuration file is written. Jev and Parallel are not involved.
